# PRD — LiteOC 配置抽取

> **Status: 已实现**(D1–D7、D9 实测通过;D8 跨版本合并未做,当前 schema 稳定)。仓库:github.com/ren2019/LiteOC(private)
> 关联:`CONTEXT.md`(术语)、`docs/adr/0001`、`docs/adr/0002`、`docs/config-spec.md`(决策明细 D1–D9)

## Problem Statement

LiteOC(菜单栏 App)+ Root Helper 现在把**所有连接参数写死在代码里**:网关地址、用户名、用户组、证书指纹、钥匙串键名、以及"判断已连/读取分到 IP 的网段正则"。后果:

- 网关换 IP、证书更新、换账号、换 AnyLink 部署 → 都得改 Swift/shell 源码、重新编译。
- 分到的内网 IP 用**写死的网段正则**猜,VPN 地址池一变就显示不出来。
- 证书指纹必须**事先知道**,而**开通邮件从不带证书指纹** → 光一封邮件配不齐。

从用户视角:我想要"改连接参数不动代码",PIN 仍只走钥匙串,且**一封标准 AnyLink 开通邮件即可配齐**。

## Solution

把所有**非机密**连接参数抽到一个用户可编辑的 **KEY=VALUE 配置文件**;PIN 仍只存 macOS 钥匙串。具体:

- 网关 / 用户 / 组 / 证书指纹 / 钥匙串键 → 配置文件可改。
- 分到的 IP 改为**从 openconnect 自身输出自动取**(不猜网段)。
- 证书指纹**可选**:留空则首次连接**自动锁定(TOFU)并回写**配置。
- 配置缺/错 → **fail loudly**,指名道姓报错,不静默兜底。
- openconnect 二进制路径**写死**(root 执行安全边界),由安装器统一 `brew install`。
- 配置跨版本升级时**自动补缺失项**,保留用户改动。

## User Stories

1. 作为 VPN 用户,我想在文本文件里改网关地址,这样 IT 换 VPN IP 时我不用重编译。
2. 作为 VPN 用户,我想改用户名 / 用户组 / 证书指纹,而无需碰代码。
3. 作为 VPN 用户,我想改"PIN 存在哪个钥匙串条目",以便自定义或隔离。
4. 作为 VPN 用户,我想让 PIN **永不**出现在配置文件里,始终只在钥匙串。
5. 作为 VPN 用户,我想从菜单一键打开配置文件(用文本编辑器)。
6. 作为 VPN 用户,我想首次启动时自动生成带注释的默认配置模板,免得手写。
7. 作为 VPN 用户,我想改完配置保存后**不用重启 App**就生效。
8. 作为 VPN 用户,配置写错时,我想看到**指名道姓**的报错(哪个字段、期望什么),并能一键打开配置。
9. 作为 VPN 用户,我不想让写错的值被**静默兜底**掩盖(如证书指纹错了却连上旧默认证书)。
10. 作为 VPN 用户,证书指纹格式不对时,我想被明确告知(须 `pin-sha256:` 开头)。
11. 作为 VPN 用户,收到一封**只有网关/用户/组/PIN**的开通邮件时,我想直接配齐、无需额外信息。
12. 作为 VPN 用户,我不知道证书指纹时,我想首次连接**自动锁定**它,不用自己探测。
13. 作为 VPN 用户,自动锁定的指纹我想被**写回配置**,之后每次都严格校验。
14. 作为 VPN 用户,证书被换(中间人或正常轮换)时,我想连接**失败报警**,而不是悄悄连上。
15. 作为正常证书轮换后,我想清空证书字段即可重新锁定。
16. 作为 VPN 用户,我想菜单显示**真实分到的内网 IP**,即使地址池变了也对。
17. 作为 VPN 用户,我想菜单准确反映 未连接/连接中/已连接 三态。
18. 作为 VPN 用户,我想连接中有一个**加载态**指示(图标彩/灰闪烁)。
19. 作为同事,我想用同一个 App、只改用户名 + 存自己的 PIN 就能连(钥匙串天然隔离各人 PIN)。
20. 作为另一个 AnyLink VPN 的用户,我想把 App 指向我的网关(改 4 个字段 + PIN),工具不被绑死在一家公司。
21. 作为用户,我想工具**不假装**支持它搞不定的协议(OpenVPN/WireGuard/IPsec 等),期望清晰。
22. 作为新装用户,我想 openconnect 被**自动安装**,二进制路径确定、不用我手动找。
23. 作为新装用户,openconnect 缺失时我想收到清晰提示去装,而不是莫名失败。
24. 作为注重安全的用户,我想 openconnect 路径**不可由配置指定**,杜绝"让 root 执行任意程序"的提权后门。
25. 作为注重安全的用户,我想配置只被**解析、不被执行**(不 `eval`),防 shell 注入。
26. 作为注重安全的用户,我想配置文件**不含任何机密**(无 PIN),无需特殊文件权限。
27. 作为用户,App 升级后我想**新配置项自动补上**,且**我改过的值不丢**。
28. 作为用户,我想配置永远完整,升级后不会因缺项误触发 fail-loudly。
29. 作为用户,我想菜单"已连接 + IP"那行**正常色**,不要灰成"不可用"的语义。
30. 作为用户,我想不可用的按钮(如已连接时的"连接")**置灰**,可用的高亮。
31. 作为用户,我想菜单栏图标用 App 图标(地球),**彩色=连上、灰色=离线**。
32. 作为用户,我想断开走优雅关闭(SIGINT),路由被自动清理。
33. 作为用户,连接失败时我想看到**真实原因**(证书不匹配 / 用户名密码错 / 网络不通),来自 openconnect 日志。
34. 作为用户,我想配置里的证书指纹(含 `/` 和结尾 `==`)被正确解析、不被截断。
35. 作为维护者,我想配置层是**纯逻辑、可单测**,bug(解析边界、fail-loud 判定)能被 fixture 抓住。

## Implementation Decisions

- **配置单位 = 单 Profile**(D1):一个配置文件描述一个 VPN;结构按单 profile,将来可扩 `profiles[]`。
- **范围**(D2):网关 / 用户 / 组 / 证书指纹 / 钥匙串键 → 配置;openconnect 二进制路径 / App 名 / Root Helper 路径 / PIDFILE / 旧迁移名 → 写死。
- **配置 schema**(决策富集,原样保留键名):
  ```
  HOST="host:port"
  USER="用户名"
  GROUP="用户组"
  SERVERCERT="pin-sha256:…"      # 可选;空则首次自动锁定(D9)
  KEYCHAIN_SERVICE="LiteOC"
  ```
  (KEYCHAIN_ACCOUNT 曾在此 schema 中;2026-08-21 决议移除——App 只写不读,唯一消费者 connect.sh 收缩后无人使用。account 固定 `"pin"` 写死在代码。)
  解析规则:按"第一个 `=` 之后全部"取值(证书指纹含 `/`、结尾 `==` 不被截断),去首尾引号,`#` 为注释。
- **状态/IP 探测自动**(D3):连/断 = `pgrep openconnect`;分到的 IP = 从 openconnect 自身输出的 `Configured as <ip>` 取。移除"网段正则"配置项。
- **openconnect 路径写死 + 安装器统一装**(D4,见 ADR-0001):Root Helper 用写死的固定路径清单找 openconnect;安装器负责 `brew install openconnect`(用户级),装前校验存在。
- **格式与位置**(D5):KEY=VALUE(带 `#` 注释),用户主目录下标准"应用支持"目录;首次启动写默认模板;菜单"编辑配置…"用文本编辑器打开。
- **OTP 不加**(D6):纯 PIN;服务器实测只校验 PIN。将来需要再加。
- **校验与失败 = fail loudly**(D7):连接前校验必填项非空、`SERVERCERT` 非 `pin-sha256:` 开头(若非空)即报;违规弹窗指名道姓 + 打开配置按钮;openconnect 失败显示真实原因;**不静默兜底默认值**;校验时机为点"连接"时。
- **跨版本升级 = 自动合并缺失项**(D8):启动时缺的键追加默认值 + 注释,保留用户已改值,配置永远完整。
- **证书指纹可选 + 首次自动锁定 TOFU**(D9,见 ADR-0002):`SERVERCERT` 空时,首次连接主动获取网关证书 `pin-sha256`(openconnect 报出 / TLS 探测),用它连接并把 pin 回传 App;由 **App(用户态)**写回配置(不让 root 改用户文件致属主错乱);之后严格校验。
- **数据流**:用户编辑配置 → App 读配置 + 取钥匙串 PIN + 连接前校验 → 把配置路径传 Root Helper → Root Helper 安全解析(不 eval)+ 校验 + (pin 空则自动取并回传)+ 用写死的 openconnect 后台连接、输出记固定日志 → App 显示状态/pgrep、IP 取自日志。
- **菜单 UI 修复**:状态行(已连接+IP)由"禁用灰"改为正常色;不可用按钮置灰;图标用 App 图标(彩=连、灰=断、闪烁=连中)。
- 遵循 ADR-0001(openconnect 路径不进用户配置)、ADR-0002(证书 TOFU)。

## Testing Decisions

**好测试的标准**:只测外部行为(给定输入 → 期望输出/报错),不测实现细节;不 mock 整个世界。

**唯一自动化 seam — 配置层纯逻辑(fixture 驱动)**:
- 覆盖:解析 KEY=VALUE(含证书指纹 `/`+结尾 `==` 不截断)、校验(必填 + 证书格式 → fail-loud 判定)、证书 pin 抽取(D9,喂 openconnect 输出片段断言取到正确 pin)、配置合并(D8 缺项补默认且保留用户值)。
- fixture 集(两实现共用):`valid` / `missing-key` / `bad-cert-format` / `empty-servercert` / `cert-with-special-chars` → 期望解析值 + 校验通过/报错。
- 两个薄驱动:Root Helper 侧(shell 喂 fixture)、App 侧(把 loadConfig/validate **抽成可测纯模块**,XCTest 跑同一份 fixture)。
- 含义:App 的配置逻辑需从"内联"**抽成可测模块**——这本身是该做的重构。

**手动集成清单(不自动化)**:对真实 AnyLink VPN 跑 connect/disconnect/status,覆盖:纯 PIN 连上、TOFU 首次锁定与回写、IP 正确显示、断开路由清理、fail-loud 各类报错、升级后配置合并、多账号(改 USER+PIN)。为何手动:依赖 sudo + 钥匙串 + 活服务器,mock 失真、CI 连生产 VPN 不现实。

**先例**:本仓库当前无测试,本 seam 为首个测试基建。

## Out of Scope

- **OTP / TOTP**(D6 砍):服务器只要 PIN;客户端动态码它不认。
- **多 Profile 切换**(D1 推迟):当前单 VPN;结构预留 `profiles[]` 扩展。
- **非 openconnect/AnyConnect-SSL 协议**:OpenVPN / WireGuard / IPsec / SangFor EasyConnect 专有协议。
- **SSO / SAML / 浏览器交互登录**(Okta、钉钉扫码等)。
- **客户端证书认证**。
- **跨平台**:仅 macOS(菜单栏 App 为 Swift/AppKit);Linux/Windows/iOS 不做。
- **路径式 group(--usergroup)服务器**:当前认证写死 AnyLink 的"密码+group 走 stdin";非 group 或路径式服务器暂不保证。

## Further Notes

- **适用范围**:做完后,LiteOC 从"绑死一个网关"变为"**AnyLink 这一类**的轻量客户端":同一公司可给同事用(改 USER + 各自 PIN),不同 AnyLink 部署改 4 个网关字段 + PIN 即用。AnyLink 在国内中小公司较常见,是个实在受众。
- **再扩面的杠杆**(均曾被推迟/砍掉,按需复活):认证模式可配(group 可空/支持 `--usergroup`)、OTP 复活、多 Profile、跨平台 GUI 重写。
- **安全边界**是本设计的核心约束(ADR-0001):凡 Root Helper 会"当作程序执行"的路径,不得来自用户可写配置;其余字段只是 openconnect 参数、安全。配置只解析不执行。
- **回写属主**:D9 的证书回写由 App(用户态)执行,Root Helper 只返回 pin,避免 root 改用户文件造成属主错乱。
